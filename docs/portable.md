# Переносной фотоархив для Windows

## Какой архив скачать

Откройте [последний релиз](https://github.com/arxey/LocalInterfaceWeb/releases/latest) и в **Assets** выберите **`LocalInterfaceWeb-Windows-x64.zip`**. Его можно заранее скачать на другом компьютере и принести на флешке. После распаковки интернет для запуска, входа и работы с фотографиями не требуется.

Архивы **Code → Download ZIP** и **Source code** содержат исходники для разработки. В них отсутствуют встроенные среды `runtime/` и готовый интерфейс `frontend/dist/`; такой архив не запускается офлайн двойным щелчком.

## Что нужно на компьютере

Windows 10/11 x64, браузер и папка, в которую текущему пользователю разрешена запись. Распакуйте весь архив, например в «Документы». Не запускайте из окна ZIP и не помещайте рабочую копию в `Program Files` или на носитель только для чтения. Для продолжительной работы удобнее распаковать на локальный диск.

Права администратора, Docker, WSL и отдельные установки Python, Node.js, PostgreSQL, pgAdmin, VS Code или PyCharm не нужны. Скрипт не устанавливает службы Windows и не требует настройки реестра или PATH. Если AppLocker или другие правила учреждения блокируют запуск, запросите разрешение ответственного администратора.

## Запуск и вход

1. Дважды нажмите **`start-portable.cmd`** в распакованной папке.
2. При первом запуске дождитесь создания локальной БД, применения миграций и подготовки учебной фотографии. Откроется браузер; в консоли появится строка **`Ready`** с адресом.
3. Для просмотра вход не требуется. Чтобы добавлять, изменять и удалять фото, нажмите «Войти» и используйте показанные в консоли имя `admin` и случайный пароль.
4. Оставьте окно запуска открытым, пока работаете с фотоархивом.

Обычный адрес — [http://127.0.0.1:8080](http://127.0.0.1:8080). Если порт занят, выбирается другой свободный порт; используйте адрес из консоли. Текущий адрес также записан в `data/running.json`. Веб-сервер и PostgreSQL слушают только `127.0.0.1`, поэтому приложение не открывает фотоархив другим компьютерам сети.

Первоначальный пароль хранится в `data/config.json`. Если вы изменили пароль самой учётной записи, используйте новый: перезапуск его не сбрасывает, а сохранённый первоначальный пароль автоматически не обновляется.

При запуске из командной строки доступны:

```bat
start-portable.cmd --no-browser
start-portable.cmd --headless
```

`--no-browser` оставляет адрес и пароль в консоли, но не открывает браузер. `--headless` дополнительно скрывает учётные данные. Обычный двойной щелчок не требует параметров.

## Остановка

Дважды нажмите **`stop-portable.cmd`** из той же папки либо нажмите **Ctrl+C** в стартовой консоли. Дождитесь окончания остановки. Закрытие браузера не останавливает сервер и БД.

Перед переносом, копированием резервной копии или извлечением флешки всегда выполняйте эту остановку. Не удаляйте `data/`, если нужно сохранить коллекцию.

## Где находятся программа и данные

| Путь | Назначение |
|---|---|
| `runtime/python/` | Встроенный Python 3.14.10 с нужными библиотеками |
| `runtime/postgresql/` | Встроенный PostgreSQL 18.7, включая утилиты командной строки |
| `backend/`, `frontend/dist/`, `portable/` | Сервер Django/Waitress, собранный интерфейс и запуск |
| `demo/` | Учебное изображение для новой установки |
| `data/config.json` | Выбранные порты, имя администратора и локальные секреты |
| `data/postgres/` | Каталог базы PostgreSQL |
| `data/media/` | Оригиналы фотографий и миниатюры |
| `data/static/` | Подготовленные статические файлы Django |
| `data/logs/` | Журналы запуска, сервера и БД |
| `data/tmp/` | Временные файлы |

`data/` создаётся при первом запуске. Свежий релизный архив не содержит пользовательской базы, загруженных фото или готовых паролей. Пути приложения вычисляются заново при запуске, поэтому рабочую копию можно переносить целиком.

`data/config.json` содержит секреты: `django_secret`, `database_password`, `superuser_password` и `admin_password`. Не добавляйте его в Git, публичные архивы, скриншоты или отчёт. Доступ к этой папке означает доступ к вашей локальной установке.

## Перенос и резервная копия

1. Остановите сервис через `stop-portable.cmd` и дождитесь завершения.
2. Скопируйте **всю папку приложения вместе с `data/`** на другой диск или флешку. Сохраните ещё одну копию, если это резервное копирование.
3. На другом компьютере с Windows 10/11 x64 поместите папку в доступное для записи место и запустите `start-portable.cmd`.

Отдельная копия только исходников не содержит ваших фото и БД. Не отделяйте `config.json` от соответствующего `data/postgres/`: новые случайные пароли не откроют уже существующую базу. При переносе между копиями одной версии используйте всю папку; независимая свежая установка создаёт собственную пустую БД и учебный снимок.

Для обновления сначала сохраните остановленную рабочую папку целиком. Распакуйте новый релиз отдельно и следуйте примечаниям именно этого релиза. Не заменяйте встроенный PostgreSQL другой основной версии поверх существующего `data/postgres/`: для такого перехода нужен экспорт и импорт БД.

## Подключение к базе по желанию

Для работы фотоархива pgAdmin не нужен. Если он уже доступен и требуется показать таблицы преподавателю, запустите фотоархив и зарегистрируйте сервер с такими параметрами:

| Поле | Значение |
|---|---|
| Host | `127.0.0.1` |
| Port | `database_port` из `data/config.json`; обычно `55432`, при занятости другой |
| Maintenance database | `photo_service` |
| Username | `photo_service` |
| Password | `database_password` из `data/config.json` |

Это пароль БД, а не пароль входа в фотоархив. Устанавливать отдельный PostgreSQL или запускать Docker для подключения не нужно. Секреты вводятся локально; не публикуйте снимок `config.json`.

В комплекте также есть `psql`. Из командной строки в папке приложения выполните команду ниже. Если `database_port` отличается от `55432`, подставьте выбранный порт после `-p`:

```bat
runtime\postgresql\bin\psql.exe -h 127.0.0.1 -p 55432 -U photo_service -d photo_service -W
```

Пароль введите по запросу; не записывайте его в команду. Пример просмотра таблицы:

```sql
SELECT id, title, search_title, image, thumbnail, created_at, updated_at
FROM photos_photo ORDER BY created_at DESC, id DESC;
```

Docker-вариант с pgAdmin описан отдельно в [README](../README.md#postgresql-и-pgadmin); его настройки `.env.docker` и внутренний адрес `db:5432` не относятся к переносной версии.

## Если запуск не получился

| Сообщение или ситуация | Действие |
|---|---|
| `Incomplete portable ZIP` или отсутствует bundled runtime | Скачайте **готовый Windows-архив** из Assets и распакуйте полностью; Source code ZIP недостаточно |
| Папка доступна только для чтения | Распакуйте в «Документы» или другую папку с разрешённой записью |
| Порт 8080 занят | Дождитесь `Ready` и используйте выбранный свободный адрес из консоли |
| Браузер не открылся | Вручную откройте адрес `Ready`; он также есть в `data/running.json` |
| Установка уже запущена | Используйте показанный адрес или остановите эту копию через её `stop-portable.cmd` |
| База есть, но `config.json` пропал | Восстановите исходный `config.json` из своей резервной копии; не создавайте новый поверх рабочей БД |
| Ошибка подготовки БД или сервера | Сохраните данные и посмотрите `data/logs/setup.log`, `server.log`, `postgresql.log`; не удаляйте БД для «исправления» |

Для разработки и необязательного контейнерного запуска используйте [README](../README.md). Переносная папка и Docker-тома не синхронизируют данные автоматически.
